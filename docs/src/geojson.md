# GeoJSON of a view

A build with the `geojson` feature (`cargo build -p antares-broker --features geojson`)
serves the Entities of one type of a view as an RFC 7946 `FeatureCollection`, each `location` its geometry and the other Attributes its properties.

```text
GET /x/views/{view}/geojson/v1/{type}
GET /x/views/{view}/geojson/v1/{type}?limit=10&offset=10
GET /x/views/{view}/geojson/v1/{type}?q=name=="Urpín"
```

Mount it with `ANTARES_API_SURFACES=admin,views,geojson`. Each request is one
NGSI-LD Query Entities of `{type}` through the view: the view's rules, the
Policy and the Tenant decide as they do for an NGSI-LD client, so a type or an
Attribute the view hides is absent. `q`, `scopeQ` and `lang` mean what they mean
there; `limit` is 1 to 100 (default 100) and `offset` a whole number. Any other
parameter, or one given twice, is `400`.

The answer is `application/geo+json`, an RFC 7946 `FeatureCollection`: a
`Feature` per Entity, its `id` the Entity's, its `geometry` the `location`
value (the first instance of a multi-instance one, `null` without one) and its
`properties` the other Attributes as plain values: a Property's `value`, a
Relationship's `object`, a LanguageProperty's `languageMap`, a list of each
instance's for a multi-instance Attribute, and `type`. The foreign member
`nextOffset` is the `offset` of the next page, `null` on the last.

A view that is unknown, does not allow `query_entities` or does not show
`{type}` answers `404`. A read the Policy refuses answers the NGSI-LD refusal
(`403`). `HEAD` answers like `GET` without the body; every other method but
`OPTIONS` is `405` with `Allow`.

## Named outputs and CSV

A view's `representations.geojson` list ([Views](views.md)) names outputs:
`GET /x/views/{view}/geojson/v1/{name}` serves the output `{name}` over the
types of its `sources` the view shows, a name no output lists being the type
of that name as above. Each source maps roles to Attribute paths (a list:
the first with a value wins):

| Role | What it gives the Feature | Default |
|---|---|---|
| `geometry` | its `geometry`, the first path holding a valid one (`location`, `observationSpace`, `operationSpace` or a model GeoProperty) | `location` |
| `instant` | JSON-FG `time: {instant}` | none |
| `start`, `end` | JSON-FG `time: {interval: [start, end]}`, `..` for the open side | none |
| `properties` | `type` and these paths (`address.addressLocality` reads into a value) | every other Attribute |

The output's `filter` is AND-ed with the caller's query: its `q` as
`(filter);(caller's)`, its `scopeQ` intersected with the caller's, and a
fixed geo-query the caller may not replace (`400`). The view and the Policy
still decide per Entity, so an output never serves an Entity or Attribute the
view hides. `lang` is the default of the caller's, `limit` the default page
size. An output whose members do not hold answers `500`, one none of whose
types the view shows `404`.

`GET /x/views/{view}/csv/v1/{name}.csv` serves the output `{name}` of
`representations.csv` (or the type `{name}`) as RFC 4180 CSV: `id`, then
`type` when the output maps several types (a union), then each source's
`columns` role in order (default every Attribute its Entities hold, sorted),
one row per Entity up to the output's `limit` (at most 10000). `q`, `scopeQ`
and `lang` narrow it; a cell a spreadsheet would read as a formula is written
as text. A file past 4 MiB is `413`, never cut short.

The conformance pack is [`tests/geojson/README.md`](https://github.com/marek-mraz-jc/Antares-NGSI-LD-Context-Broker/blob/dev/tests/geojson/README.md);
the crate was generated by `dev/new-surface.py` ([New surface](new-surface.md)).
